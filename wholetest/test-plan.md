# 1 目的与范围

## 1.1 目的

本文规定 EtherCAT 主站在**服役条件下**必须通过的考验，以及为证明其通过所必须采集的记录和判定规则。

考验的取值来自主站所接触的世界，不来自其实现，也不来自开发过程。任何实现变更都不改变场景集合；实现变更只改变"是否通过"。

## 1.2 范围

覆盖：主站进程、其配置体系、其对外接口（命令口、观测口、报告与归档）。

不覆盖：
- 上层应用（本文记为 L6，位于本仓库之外）的功能正确性
- 驱动器固件内部行为。主站只能观测其对外表现，本文只对主站**对这些表现的处置**提出要求
- 机械与工艺安全（限位、制动、人员防护）。本文只要求主站在这些条件发生时**行为可预期且可追溯**

## 1.3 与其它文档的关系

| 文档 | 关系 |
| --- | --- |
| 本文件 | 主控测试规格。场景编号、记录项编号、判定规则编号的唯一来源 |
| `scenarios.tsv` | 第 7 章的机器可读摘录，供工具消费 |

| 术语 | 含义 |
| --- | --- |
| 装置 | 被测系统 + 其连接的物理世界（总线、从站、供电、主机） |

# 4 被测系统

## 4.1 系统边界

主站在以下界面上与外界接触。每一个界面即本文的一条变化轴。

| 边界 | 界面 |
| --- | --- |
| B1 | 物理层（网口、线缆、供电、电磁环境） |
| B2 | 从站（数量、型号、换算参数、个体健康、初始位置） |
| B3 | 总线协议（过程数据帧、分布式时钟、邮箱、从站状态机） |
| B4 | 宿主（调度、资源、时钟、网络） |
| B5 | 上层命令（命令口） |
| B6 | 操作与生命周期（启停、时长） |
| B7 | 配置与实车（声明值与实际装置的关系） |
| B8 | 观测与取证自身（观测口、报告、归档） |

## 4.2 契约

主站的契约由两类条款构成，二者地位相同。

**必须做到的**：在给定条件下，主站必须产生的行为。

**必须拒绝的**：在给定条件下，主站必须拒绝进入的状态，以及拒绝时必须给出的信息。

本文第 7 章每一条场景都标注其属于哪一类。**只测肯定面不测否定面，等于只测了契约的一半。**

# 5 测试策略

## 5.1 方法（六条原则）

| 编号 | 原则 | 含义 |
| --- | --- | --- |
| M-1 | 判据先于执行 | 每个场景执行前先写下判定准则，且准则必须可由机器判定。以结果反推准则等于以结果定义标准 |
| M-2 | 单变量 | 一次只让一条变化轴动。同参数重复仅回答"是否随机"，不回答"为什么" |
| M-3 | 记录自足 | 判定必须能由第三方仅凭记录重算，不需作者在场、不需补充说明 |
| M-4 | 测等价类与边界 | 每条变化轴上取分界值与等价类代表；连续取值测边界，不测中间 |
| M-5 | 否定面与肯定面并重 | "必须拒绝"的场景与"必须做到"的场景同等必测 |
| M-6 | 判定独立于开发过程 | 判定端只读记录与被测物契约，不读开发史、不读提交记录、不假设历史故障形态 |

## 5.2 测试层次

| 层次 | 是否需要装置 | 说明 |
| --- | --- | --- |
| L-A 离线 | 否 | 不接总线的确定性验证：单元、协议解析、配置一致性、报告渲染、工具行为 |
| L-B 台架 | 是 | 接实际总线，按场景驱动 |
| L-C 现场 | 是 | 长时、跨天、真实工况 |

**层次归属不改变场景编号。** 同一场景在不同层次上的判定准则可以不同（例如 B4 的调度类场景只能在 L-B 上取得真值）。

## 5.3 判定框架

每个场景的判定输出三值之一：

| 判定 | 含义 |
| --- | --- |
| 通过 | 记录完备，且满足该场景的全部判定准则 |
| 不通过 | 记录完备，且违反至少一条判定准则 |
| 无法判定 | 记录不完备，或判定准则所需的值缺失。**该值不得以默认值代替** |

**"无法判定"是一个正式结论，不是失败，也不是通过。** 把它并入任何一侧都会污染结论。

# 8 记录项规范

## 8.1 采集判据

**凡是两次运行之间可能不同、而判定时假定其相同的量，都必须记录。**

理由：对照判定的前提是"除被测变量外其余一致"。记不下来的量无法证明一致，该次运行的判定即不可复核。

| R-E3 | 同步统计 | 周期、移位、相位、裕量及其极值 | 键值 | `na` |
| R-E4 | 异常事件 | 每个异常的类型、首次与末次出现的坐标、当时的逐轴状态 | 事件序列 | `na` |
| R-E5 | 状态迁移 | 会话状态机各次迁移的坐标，以及停机各阶段的逐轴快照 | 序列 | `na` |
| R-F1 | 判定结论 | 三值结论、所依据的规则编号、以及未能证实的部分 | 结构化文本 | 必填 |
| R-F2 | 判定规则集 | 本次判定所用的规则编号与版本 | 列表 | 必填 |

## 8.3 全局必需记录项

下列记录项不问场景，**每一轮都必须采集**。理由是 M-3（记录自足）：没有它们，判定无法由
第三方重算，该轮的全部场景结论一律降为"无法判定"。

| 编号 | 名称 | 为什么每一轮都要 |
| --- | --- | --- |
| R-A1 | 代码版本 | 否则"这一轮跑的是什么"无法确定 |
| R-A2 | 配置摘要 | 同上；且判定要用配置推算期望值 |
| R-A3 | 二进制摘要 | 源码相同不等于装置上跑的相同 |
| R-F2 | 判定规则集 | 否则结论无法复核 |

## 8.4 缺失与未知

`na` 表示"该项存在但未取到"，`unknown` 表示"该项未被采集"。

**两者都不得以零值、默认值或空串代替。** 零在多数记录项上是合法取值（零电流、零转速、零错误），以零代替缺失会把"未取到"读成"确实为零"。

任何以缺失项为依据的判定，结论为**无法判定**（见 5.3）。

# 9 判定规则

| 编号 | 规则 |
| --- | --- |
| V-01 | 记录完备性：场景所需的记录项全部非 `na`/`unknown` 时，方可给出通过或不通过；否则为无法判定 |
| V-02 | 计数判据：帧异常的两类计数分别与各自阈值比较，不得合并 |
| V-03 | 状态判据：会话终态的各轴状态必须全部处于约定状态；存在未应答轴时按不通过处理 |
| V-04 | 跟随判据：任一周期的跟随误差达到该轴整条位移量级时，判定为死轴 |
| V-05 | 一致性判据：期望计数与从站数的关系必须成立；不成立时判定为不可比，需先查装置构成 |
| V-06 | 拒绝判据：否定类场景中，除"拒绝"之外的任何结果（含部分接受、静默忽略、成功）均为不通过 |
| V-07 | 可复核判据：判定过程不得依赖记录之外的任何信息；违反时判定无效 |
| V-08 | 三值判据：无法判定不得并入通过或不通过；出现无法判定即表示记录规范需要修订 |

各判据的**阈值**须经批准后方可生效，并随本文版本化。未批准前，判定端只输出原始量，不给三值结论。

# 11 覆盖现状

本节描述**当前工具的覆盖面**，不含任何历史事件。它以本文为基准，标出哪些场景已有支撑手段、哪些没有。

| 边界 | 已有支撑 | 缺口 |
| --- | --- | --- |
| B1 物理层 | 接口状态可读；扫描工具存在 | 链路状态的时间序列未采集；上电顺序未被作为变量 |
| B2 从站 | 扫描工具可给出数量、身份、换算 | 逐轴身份与换算未进入每轮存档；死轴判定需人工 |
| B3 总线协议 | 两类帧异常分别计数；同步量可读 | 阈值未批准，判定端只输出原始量 |
| B4 宿主 | 调度实测值在报告中 | 采集不完整（资源限制、竞争负载）；相关场景未建立 |
| B5 上层命令 | 拒绝路径可读；失活降级已实现 | 非法输入的注入场景未建立 |
| B6 生命周期 | 停机各阶段快照在报告中 | 长时与跨天场景未建立；重启间隔未作为变量系统化 |
| B7 配置与实车 | 四项核对（数量/身份/换算/映射）均会拒绝 | 声明值与实测值未成对存档 |
| B8 观测与取证 | 观测开关存在 | 开关对照未做；截断与写满场景未建立 |

**B4、B6、B8 三处最薄**，其共同特点是不接总线亦可开展。
