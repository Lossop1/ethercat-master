# EtherCAT 官方资料调查基线

> 调查日期：2026-09-02  
> 状态：第一轮调查记录，后续以真机证据补充，不作为已经完成运动控制的声明。

## 1. 调查目的

本记录用于建立从站上电到多轴周期控制的共同基线。调查不局限于 `6061` 模式显示，而是把官方资料中的状态切换、PDO、SDO、DC、CiA 402、故障和通信监控规则，与当前主站实现及真机读数逐项对应。

本项目当前可用的正式资料及职责如下：

## 3. 官方流程基线

### 3.1 上电和 EtherCAT 状态机

供应商手册第 5.1 节给出的 AL 状态为 `INIT -> PRE-OP -> SAFE-OP -> OP`，回退方向相反。手册说明在 OP 状态下 SDO、TxPDO、RxPDO 均有效；PDO 分配和其他启动配置应在 PRE-OP 完成。

正确顺序是：

1. 确认驱动器供电、EtherCAT 线缆和专用网口。
2. 主站发现从站并核对厂商 ID、产品码和修订号。
3. 进入 PRE-OP，建立邮箱通信，读取并核对实际 PDO 分配和映射。
4. 在 PRE-OP 完成允许的 SDO/PDO 分配配置和启动参数写入。
5. 配置过程数据映射，建立过程映像，发送首帧并核对 WKC。
6. 配置 DC/Sync0 后请求 SAFE-OP，确认输入反馈有效。
7. 在 SAFE-OP 中按运行方案持续交换过程数据，使用从站 DC 时间校正主站周期，达到方案规定的稳定周期数。
8. 请求 OP；确认 OP 后才执行 CiA 402 周期控制。

### 3.2 PDO 分配和映射

供应商手册第 5.7 节明确指出：映射对象固定，PDO 分配可选；当前设备支持一个 RxPDO 分配和一个 TxPDO 分配。

- `0x1C12:01` 选择 `0x1600`、`0x1601` 或 `0x1602`。
- `0x1C13:01` 选择 `0x1A00`、`0x1A01` 或 `0x1A02`。
- 重新配置组时，先向 `0x1C12:00` 或 `0x1C13:00` 写入 `0`，再写入映射组索引，最后写回组数量。
- PDO 配置只能在 PRE-OP 进行；手册说明该配置不能保存到 EEPROM，每次上电都必须重新配置。
- 写入不支持的映射组或在非 PRE-OP 写入应产生 SDO 错误。

当前 ESI 的动态模块 `0x119800` 对应：

- RxPDO `0x1600`：`6040`、`607A`、`60FF`、`6071`、`6060`、8 位填充，共 14 字节。
- TxPDO `0x1A00`：`6041`、`6064`、`606C`、`6077`、`6061`、8 位填充，共 14 字节。

ESI 另定义 `0x219800` 的 CSP 模块和 `0x319800` 的 CSV 模块；它们分别使用较短的固定 PDO。运行方案必须明确选择模块，不能把不同模块的过程映像混用。

### 3.3 SDO 和 SO 初始化

供应商手册把 SDO 定义为邮箱中的非周期数据，用于通信参数和驱动运行参数配置。ESI 中还存在 `Transition=SO` 的启动命令：

- CSP 模块：`6060:00 = 08`；
- CSV 模块：`6060:00 = 09`。

因此必须区分两件事：

1. PRE-OP 中通过 SDO 写入对象；
2. 从 SAFE-OP 到 OP 的 SO 初始化命令。

当前运行方案使用动态模块 `0x119800`，而该模块本身没有嵌套的 `SO InitCmd`；当前主站在 PRE-OP 通过 SDO 写入 `6060`。这是否等价于官方 TwinCAT 的 SO 初始化时序，仍需用官方流程和真机读回确认，不能直接假定等价。

### 3.4 DC/Sync0

供应商手册第 1.3 节规定设备使用 DC 同步，并给出以下约束：

- 主站用 Sync0 周期决定通信周期；
- 必须保证 Sync0 发生在 SM2 事件之后；
- 主站周期抖动、未收到首个 DC 从站的同步信号或周期配置错误，可能触发同步错误并退回 SAFE-OP；
- TwinCAT 可用 Sync0 延时（手册拼写为 `Shit time`）给 SM2 数据复制留出余量，推荐延时为周期的四分之一。

ESI 的 DC 选项为 `AssignActivate=#x300`。当前批准运行方案为 1 ms 周期、250 us Sync0 偏移、SM2 类型 `0x0001`、SM3 类型 `0x0022`。ESI 读回的最小周期为 31.2 us；供应商手册给出的单从站实验室最小 DC 周期为 41.1 us，因此 1 ms 在设备能力范围内，但不代表主机实时性已经达标。

### 3.5 CiA 402 状态和周期控制

供应商手册第 5.2 节的状态图及控制表给出基本顺序：

`0x0006`（伺服准备好） -> `0x0007`（等待打开伺服使能） -> `0x000F`（伺服运行）。故障状态必须先按 CiA 402 故障复位流程清除，不能仅凭再次发送 `0x000F` 恢复。

三种周期模式及必要过程数据为：

- CSP（模式值 8）：周期发送 `607A` 目标位置，反馈 `6064` 实际位置；
- CSV（模式值 9）：周期发送 `60FF` 目标速度，反馈 `606C` 实际速度；
- CST（模式值 10）：周期发送 `6071` 目标转矩，反馈 `6077` 实际转矩。

模式选择 `6060` 是命令，模式显示 `6061` 是只读反馈，二者不是控制字和状态字的替代关系。`6040` 是主站命令，`6041` 是从站状态反馈，数值不应相等。

## 4. 当前实现与真机证据

### 4.1 已覆盖的实现

当前调用链为：运行方案解析 -> 从站身份核对 -> PRE-OP PDO 发现 -> SDO 写入/读回 -> 过程映像建立 -> DC/Sync0 配置 -> SAFE-OP -> 按方案连续交换并校正 DC -> OP -> CiA 402 周期状态机 -> 安全停机 -> 关闭 Sync0 -> 恢复 INIT。

对应模块为：

- `src/session/session_plan.c`：将拓扑、设备目录和运行方案组合为轴计划，校验周期、模式和 PDO 方案；
- `src/bus/soem/control_session.c`：执行 SOEM 状态切换、SDO、过程数据、DC 和生命周期清理；
- `src/bus/soem/cia_process_image.c`：按实际 PDO 位布局编解码，不按固定字节偏移猜测；
- `src/cia402/controller.c`：解码 `6041` 并规划 `6040`；
- `src/multiaxis/coordinator.c`：对任意轴数执行同一周期的状态计算；
- `src/cyclic/exchange.c`：提供 WKC、序号和截止时间检查。

### 4.2 已有真机证据

已在 Orange Pi 的 `enp49s0`、单从站台架上验证：

- SAFE-OP、OP 均可达到；
- 稳态 WKC 为 `3/3`；
- DC/Sync0 配置、寄存器读回和关闭成功；
- CiA 402 状态路径达到运行使能；
- 周期运行约 4947 次，安全停机并恢复 INIT 成功；
- 读数示例：运行使能阶段 `6041=0x1237`、`6040=0x000F`，停止阶段 `6041=0x1233`、`6040=0x0007`；
- `603F` 已有读回值为 `0` 的证据；`6061` 通过 PDO 和 SDO 均读到 `0`。

这些证据说明 EtherCAT 帧交换、PDO 解码、DC 和基本 CiA 402 状态转换已经打通，但尚未证明运动目标控制正确。

本次继续主线的控制会话（2026-09-02）补充了以下读回结果：

- `603F=0x0000`、`1001=0x00`、`203E=0x00000000`、`203F=0x00000000`；当前没有驱动故障或通信错误证据；
- `1C32`、`1C33` 的 SM-Event Missed、Cycle Time Too Small、Shift Time Too Short 均为 `0`，Sync Error 均未置位；
- 稳态 WKC 为 `3/3`，约运行 `7900` 个周期后安全停机并恢复 INIT；
- 真实位置换算对象读回 `608F:01/02=16384/1`、`6091:01/02=28/1`。`6091:01=28` 与 EDS 默认值不同，后续必须使用物理从站读回值，不能使用目录默认值；
- `6061` 仍通过 PDO 和 SDO 读到 `0`，该差异保留为待解决兼容性问题，但不再阻塞本阶段的总线和状态机主线。

针对 `6061=0` 的写入时序假设，已在不改变位置目标的真机会话中完成两次对照：

- 在 SAFE-OP 到 OP 请求前再次通过 SDO 写入 `6060=8`，写入和读回均成功，`6061` 仍为 `0`；
- 进入 OP 后通过 SDO 写入 `6060=8`，写入和读回均成功，`6061` 仍为 `0`。

因此可以排除“只因 SDO 写入状态不对”这一解释。正式控制路径不保留这两段对照写入；后续应核对 ESI 的动态模块与固定 CSP 模块选择、PDO 分配对象以及驱动器模式反馈实现。

## 5. 当前差距和优先级

### P0：先完成故障和通信证据闭环

故障、通信和同步对象已经在同一控制会话中读回并输出；后续只需在出现异常时保留对应会话结果，不重复建立独立的 PRE-OP 测试链路。

### P0：核对 `6060` 的初始化时序

ESI 对 CSP/CSV 模块声明了 SO 初始化命令，而当前动态模块使用 PRE-OP SDO 写入。两种 SDO 时序对照均未改变 `6061=0`，所以必须继续确认官方 TwinCAT 实际选择的模块、PDO 分配对象以及驱动器模式反馈实现。`6061=0` 仍是待解决的 EtherCAT 功能问题，不能解释为普通现象。

### P1：确认 DC 的实时裕量

当前配置满足资料给出的周期和偏移，但尚未测量主站发送帧相对 SM2/Sync0 的实际到达裕量，也未在多从站拓扑下验证抖动、丢帧和同步错误计数。

### P2：再进入运动和多轴扩展

总线、DC、故障诊断和状态机链路已具备进入运动验证的条件。非零 CSP 目标仍必须由项目负责人给出物理位移和安全边界后，依据每台从站读回的 `608F/6091` 换算并发送；随后验证实际位置、限位、停机响应和多轴同周期行为。`6061` 兼容性问题继续单独跟踪，不伪造为通过。
