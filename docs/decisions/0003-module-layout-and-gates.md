# ADR 0003：领域模块和证据门槛

状态：已接受

日期：2026-08-31

## 背景

旧项目和最初基线都使用常见的 C 工程目录名。目录相似本身不能证明架构被复制，但
`src/core` 之类泛化所有权容易持续吸收不相关行为。预先创建大量空组件目录同样会在需求未知
时冻结错误抽象。

## 决策

保留标准 C/CMake 顶层布局，并为每个已经实现的领域定义一个 CMake target。使用 `catalog`
和 `bus/soem` 之类精确所有权名称。诊断可执行程序放在 `tools/`。单元、集成、回放、硬件和
实时测试在对应测试类别真实存在时分别建立。

模块必须通过 `docs/development/module-lifecycle.md` 规定的生命周期才能引入。不得为 PDO、DC、
周期执行、CiA 402、安全、监督器或 API 模块创建占位目录。只有 `src/bus/soem/` 可以包含
SOEM 头文件或调用 SOEM API。

## 影响

初始 `emaster_core` target 改为 `emaster_catalog`。PRE-OP 探测返回强类型采集数据，不再自行
写 JSON。指纹读取计划、序列化、命令行确认和文件原子发布位于 SOEM 适配层之外。后续进度按
模块证据门衡量，而不是按新增源码数量衡量。
