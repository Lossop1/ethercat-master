# 决策 0004：分离设备、拓扑与部署配置

状态：已接受

日期：2026-08-31

## 背景

初始第一阶段配置把 12 轴产品目标、当前单从站台架、Orange Pi 网卡 `enp49s0` 和 PRE-OP 安全
上限放进同一个机器人 JSON，并在通用校验器中逐项写死。这使新增型号、改变台架规模或更换主机
都需要修改通用机制，也让普通配置具备了看似可以放宽安全能力的错误语义。

产品计划包含 12 个物理位置，但当前只连接一台电机。前者是产品验收实例，后者是测试环境事实，
两者都不应成为主站核心代码的编译期假设。

## 决策

采用三个独立配置集合：

- 设备配置描述型号及修订版事实；
- 拓扑配置描述任意非空规模的逻辑从站序列；
- 部署配置描述主机、专用 EtherCAT 接口和所选拓扑。

通用校验器扫描全部配置文件，只检查结构、唯一性、位置连续性和跨层引用，不检查固定轴数或固定
网卡名。12 轴产品拓扑和单从站台架拓扑作为普通数据实例接受同一机制校验。

第一阶段 PRE-OP 上限继续由受限诊断工具的实现保证。拓扑和部署配置不能授权 PDO 映射、DC、
SAFE-OP、OP、SDO 写入或 CiA 402 使能。

## 结果

- 新增设备型号只需增加设备 JSON，构建系统自动纳入生成目录；
- 改变台架连接数量只需选择或增加拓扑和部署实例；
- 网卡冲突与 PTP/NTP 归属在部署和主机配置层解决，不污染逻辑拓扑；
- 产品验收测试仍可明确要求 12 个物理位置，但该要求不能下沉到通用校验器；
- 配置种类增加后，必须同步维护 `config/README.md`、校验器和参数化测试。
