# 硬件指纹流程

## 目的

在不映射 PDO、不配置 DC、不进入 SAFE-OP/OP、不使能 CiA 402 且不发送运动命令的前提下，
采集每个物理从站可复现的身份和配置事实。

## 前置条件

1. 电机电源和机械装置处于已批准的台架流程控制之下；
2. STO/急停行为已经独立验证；
3. 所选接口是专用 EtherCAT 网口，不承担管理、激光雷达、PTP 或 IP 业务；
4. 操作者已经记录线缆顺序和物理关节标签；
5. 已记录准确的 Git 版本和工作区是否干净；
6. 主机 UTC 时钟已经同步，并记录时间源。

## 采集

构建 Debug 预设，列出网络接口，并通过 MAC 地址和物理链路确认目标接口，然后运行：

```sh
sudo build/linux-debug/tools/fingerprint/emaster-fingerprint \
  capture records/fingerprints/<日期>-<测试装置>.json
```

目标主机、专用网卡和拓扑均来自 `config/` 中的配置，工具按当前主机名选择唯一部署，不接受
命令行覆盖。工具会在发送报文前要求操作者输入 `PRE-OP`；该确认只授权本次发现过程请求
PRE-OP，不授权任何更高状态。

## PDO 证据

采集程序先读取 `0x1C12:00` 和 `0x1C13:00` 得到实际分配数量，再按从站返回的数量逐项读取
分配索引、映射表条目数量和 32 位映射描述符。描述符会解析为对象索引、子索引、位宽和位偏移，
原始值与解析结果一并写入 schema 2 指纹。

只有下列三方全部一致时，指纹才是可批准的 PDO 基线：

1. 受控 ESI 的模块和条目；
2. `config/devices/` 中经审核的设备目录；
3. 当前物理从站在 PRE-OP 下返回的分配表和映射表。

映射表数量、索引、条目顺序、对象索引、子索引、位宽、填充项、方向总位数和字节数任一不一致，
工具都会拒绝发布指纹。PDO 发现不写 SDO，不执行 PDO 配置，不进入 SAFE-OP 或 OP。

## 评审

输出 JSON 必须有效，且 `restore_init_succeeded` 必须为 `true`。逐个从站检查：

- 线缆位置和 SII/CoE 身份；
- 型号、硬件版本、软件版本和序列号；
- 生效的 `1C12/1C13` PDO 分配；
- `1C32/1C33` 同步类型和计数器；
- 编码器分辨率、减速比、额定电流和额定转矩；
- 支持的 CiA 402 模式；
- 是否匹配目标设备目录。

任何异常或无法读取的值都是阻断项。采集会话中禁止通过写值“修复”驱动器。

## 记录保护

指纹记录属于测试证据，禁止编辑。原始文件、SHA-256、测试记录、软件版本和配置哈希必须一并
保存。

当前已批准基线为 `orangepi-bench-20260901T034149Z.json`，SHA-256 为
`08e2fcc1bfb39489a2101b026c49d290acc746e9b890f5425c5ce6d85d54e71b`。批准范围仅为
`orangepi-current-bench` 的当前单从站台架；后续更换从站、线缆顺序、拓扑或部署均须重新采集和评审。
