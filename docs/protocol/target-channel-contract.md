# 目标通道契约

这份文档定**行为**：谁给目标、一次给多少、多快给、断供之后怎么办、允许哪些模式、零点在哪里。
**线格式不在本文**：命令口的文本语法与设点口的二进制记录见
[主站接口协议 v1](command-protocol-v1.md)。本文与那份合起来才是完整的接口。

这份契约是主站与上位机之间**唯一需要冻结**的接口。规划在上位机，主站不生成轨迹、不裁剪目标、
不替客户端规划（[architecture.md:110](../architecture.md)）。所以"目标怎么送进来、送不进来会怎样"
就是产品边界本身。

---

## 1 谁给：两条入口，一个汇点

| 入口 | 形态 | 频度 | 用途 |
| --- | --- | --- | --- |
| 命令口 `set_external_target <q1> <q2> ...` | 文本，一命令一行 | 低频，手工或脚本 | 控制台点动、台架脚本、一次性置位 |
| 设点口 `/tmp/emaster-<部署ID>-sp.sock` | 二进制记录，一条一次 `send` | 客户端自定，可达数百赫兹 | 外部控制器周期送目标 |

两条入口写**同一份结构、同一把锁**，周期回调只从这一处读
（`include/emaster/motion/external_target_buffer.h:5-11`）。不存在"回调该信谁"的问题：
它只信汇点里最新那一条。

汇点语义是**覆盖式最新值**。后到的记录整条覆盖先到的，没有队列，没有积压。因此"客户端多久发一次"
不是契约的一部分（见 §3）。

**命令口这条入口不受 `EMASTER_SETPOINT` 管。** 那个开关只决定建不建设点口
（`apps/master/main.c`）。把命令口的目标入口也压到它上面，会让一个默认关的新开关废掉一条已交付的
入口，而症状是"轴不动、脚本全绿"。这条结构判据钉在 `tests/checks/target_entry_check.py`。

## 2 一次给多少：完整轴集合，按轴序

**不允许部分轴。** 一次提交必须覆盖全部轴，主站不发布部分目标集合
（[architecture.md:104](../architecture.md)）。命令口的参数个数必须与轴数完全相等，否则返回 `ERROR`；
设点记录的 `axis_count` 与本部署不等则整条拒收，不做部分采纳。

**顺序是轴序（环序）。** 第 N 个目标对应第 N 轴。**环序不等于物理关节标签**——这是当前的已知限制，
见 [README §12](../../README.md) 与差距 G-14（改用 ESC 序列号表）。在映射改成序列号之前，
上位机必须自己保证"第 N 个目标 = 它想要的那根轴"，且这份对应关系随接线变动。

## 3 多快：主站不设频率

主站不要求固定频率，也不要求与周期同频。它只问一件事：**最新那条有多旧**。

- 年龄用**主站自己的单调钟**在写入汇点时记下（`last_update_ns`），不是客户端的时标。
- 记录里的 `sequence` 与 `client_time_ns` 原样存下，只用于"丢包/重放"判定（序号只在**前进**时算缺口，
  回退或重复说明客户端重启或重放，不是丢包），**不参与超时判定**。
- 这条契约里**没有**发送序号与客户端的端到端时延（[architecture.md:116](../architecture.md)）：
  主站看不到客户端发送前的排队延迟，识别不出重放目标。

## 4 断供：退化为保持，不是失能

部署键 `external_target_timeout_ms`（默认 **200 ms**，`runtime_config.h:225-228`）到点之后，
周期回调返回 `HOLD`：**保持最后一个目标**。它不等于驱动器失能，也不是撤使能
（[README §9](../../README.md)）。

报告里能读到最近一条记录有多旧（`setpoint_last_record_age_ns`）。据此可以区分"客户端在送但很慢"与
"客户端已经断了"。

**目标量不是位置的模式下，超时不等于保持。** 那里"保持"等于让轴继续按上一条命令跑：速度模式下
继续按上一条速度跑，力矩模式下继续输出上一条力矩。所以这两种模式超时后把目标写 0，而不是留住
上一个目标（`config/README.md` 的 `quantity`）。判据是运行方案为模式声明的量，不是模式号——
回零声明 `none`，位置声明 `position`，速度声明 `velocity`，力矩声明 `torque`。

**一个部署里的所有轴共用同一个模式**：运行方案只有一个 `selected_mode_id`，主站按它给每一轴取
同一个模式对象（`src/session/session_plan.c` 的 `find_operation_mode`）。所以断供语义可以按会话
判一次；"一半轴保持、一半轴写 0"的部署在配置层构造不出来。

**未收到过任何目标时不自动跑固定轨迹。** 主站保持初始位置——首拍记下的实际位置
（[architecture.md:114](../architecture.md)、`apps/master/main.c`）。

## 5 拒收：局部、可数、不致命

被拒的是**这一条目标**，不是这次会话。其余轴照常跑，计数与现场进报告。

| 入口 | 拒收原因 |
| --- | --- |
| 命令口 | 参数个数与轴数不符；会话未配置外部目标汇点；会话不是 `RUNNING`；**目标离该轴当前位置太远** |
| 设点口 | 记录超长；格式不认识；轴数不符；模式不符（四者，见[接口协议 §拒收](command-protocol-v1.md)） |

**偏移判据是"距离"不是"增量"**（`runtime_config.h:230-242`）：判的是 `|目标 − 当前实际位置|`，
所以与客户端的发送频率无关。线的宽度由部署键 `external_target_max_offset_millidegrees`
（默认 **90°**）决定，按**每轴自己的**编码器与齿轮比折算成原始计数，所以 25:1 与 28:1 的轴得到不同
的线。

**这条判据只对目标量是位置的轴生效。** 速度与力矩模式下这条通道收的不是位置，减出来的量没有
意义，判下去等于每一条都拒（而症状是"轴不动、脚本全绿"）。所以主站只为声明了 `position` 的轴
建这条线，其余轴在报告里 `offset_limit_checked` 如实标为未判。

这道判据不是限幅，也不是速度限制。它只拦"明显不合理"：符号翻转、未初始化值、量纲错位。
**两条目标各自合法、而它们之间的速度可以任意大，主站不看这个**（[README §12](../../README.md)）。
速度与步长由客户端自己的规划负责。

## 6 允许的模式

今天接受 **5（厂商 MIT）、8（CSP）、9（CSV）、10（CST）**。判定分两步
（`src/session/session_plan.c:292-301`）：设备档的 `supported_modes` 里要有这个取值，主站的执行层
也要认得它（`include/emaster/cia402/controller.h` 的 `emaster_cia402_mode_is_supported`）。
第一步挡的是"这份运行方案配的不是这台设备"，第二步挡的是"主站还不能驱动它"，报错分开写。

**5 不是 CiA 402 定的模式**：它是厂商给 MIT 复合控制律留的取值（位置环 + 速度环 + 前馈力矩）。
它进这张表，是因为它的周期目标字段在主站这边绑得上——运行方案把它声明成位置量，映像里写
`0x6040` + `0x607A`，和 CSP 走同一条路。取值本身不构成证据：别的厂商在 5 上放什么，主站不问；
设备档没声明 5 的会话计划在第一步就把它挡掉了。增益是运行方案里的固定值（`0x2013:1`/`0x2013:2`，
每拍写进过程数据），刻度见 [config/README.md](../../config/README.md)。

- 设点记录的每个轴带 `mode`，主站按部署逐轴核对；任一轴不符，**整条记录拒收**，一个字节都不进汇点。
  同一条记录在两种模式下语义完全不同，所以不做部分采纳。
- 命令口不传模式：它写的是**该轴配置的那一种模式**，其余轴保持上次的值。
- 换模式意味着目标量变了。运行方案按模式声明这个量（`quantity`），主站据此挑目标字段与反馈
  字段、决定断供写什么、决定判不判距离——**不按模式号分支**：同一个取值在不同厂商的说明书里
  指的不是同一件事（[README §12](../../README.md)）。不能把位置客户端直接用于 CSV/CST。

回零模式（6 与 17–35）**当前被 plan 层拒绝**。要不要纳入执行层、以及纳进来之后本节怎么改，
记在差距 G-02。声明的量取 `none` 的模式就没有周期目标，这条目标通道整个不建。

## 7 零点与单位

**单位是"已按该轴换算完成的原始位置计数"。** 主站不收角度，也不猜量纲。
计数与角度、编码器与齿轮比的关系见 [README §9](../../README.md)。

- **绝对目标是"确认的起点计数 + 相对位移"**，起点由启动时的 `0x6064` 提供。
- **原始位置零点不是自动校准出的机械零点。** 回零/找机械参考点如果在产品里需要，属模式 6 的职责
  （见差距 G-02），当前无此能力。
- 换算从哪来（设备读回 / 设备档声明）也进报告；换算不可用的轴不让跑。详见
  [README §9](../../README.md) 与 [config/README.md](../../config/README.md)。

## 8 与部署、运动方案的关系

两条目标来源**二选一，且外部目标优先**：

- 部署**没有**引用固定运动方案（`motion_profile == NULL`）→ 绑定外部目标源。
- 部署**引用了**固定运动方案 → 不绑定外部源，按方案跑。

之所以是二选一：部署已经写死了轨迹，再挂一个外部源进去，动的是回调而不是配置，那么记录下来的
"本次按部署跑"就与事实不符。判断这条约定的工具是 `target_probe`。

## 9 报告与状态里的对应键

| 键 | 含义 |
| --- | --- |
| `target_rejected_count` | 被拒的目标**条数**（不是拍数） |
| `target_rejection_axis` / `target_rejection_offset_counts` | 最后一次拒收的轴号与偏移量 |
| `setpoint_enabled` | 本次是否建了设点口 |
| `setpoint_records_accepted` / `_rejected` | 设点口收发计数 |
| `setpoint_sequence_gaps` | 序号前进时缺的条数 |
| `setpoint_last_sequence` / `_client_time_ns` | 最近一条记录携带的客户端字段 |
| `setpoint_last_record_age_ns` | 最近一条记录有多旧（主站钟） |
| `setpoint_last_reject_axis` / `_reason` | 最后一次拒收的轴与原因 |

`status` 命令给的是同一批计数。完整字段表由构造它们的代码定义（`src/bus/session/session_control.c`）。

## 10 改这份契约要动哪些地方

冻结点不止一处。改动前先核对这张表，漏一处就会出现"两种说法"：

| 改动 | 必须同步 |
| --- | --- |
| 汇点语义、两条入口的关系 | `external_target_buffer.h`、`apps/master/main.c` 的绑定、`tests/checks/target_entry_check.py` |
| 拒收原因 | `include/emaster/setpoint/wire.h` 的枚举与文本、`command-protocol-v1.md` §拒收、报告键 |
| 设点线格式 | `wire.h` 的 `VERSION` +1、`src/setpoint/wire.c`、`tools/setpoint_send.py`、`tests/checks/setpoint_channel_check.py` |
| 超时 / 偏移上限的默认值 | `runtime_config.h` 的注释、[config/README.md](../../config/README.md)、[README §9](../../README.md) |
| 允许的模式 | `src/session/session_plan.c`、设备档 `supported_modes`、本节 §6、[README §12](../../README.md) |
| 模式声明的量（`quantity`） | `runtime_config.h` 的枚举与注释、`tools/gen/emaster_config.py` 的 `MODE_FIELDS`、两个校验器、本节 §4 §5 §6、[config/README.md](../../config/README.md) |
