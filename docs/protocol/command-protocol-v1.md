# 主站接口协议 v1

主站对外有三个本地套接字。三者由同一个部署 ID 推导路径，格式串各只写一份
（`include/emaster/bus/command_socket_path.h`）：

| 通道 | 路径 | 类型 | 方向 | 内容 |
| --- | --- | --- | --- | --- |
| 命令 | `/tmp/emaster-<部署ID>.sock` | `SOCK_STREAM` | 双向 | 文本，一命令一行 |
| 观测 | `/tmp/emaster-<部署ID>-obs.sock` | `SOCK_STREAM` | 只读 | 二进制帧 |
| 设点 | `/tmp/emaster-<部署ID>-sp.sock` | `SOCK_SEQPACKET` | 只写 | 二进制记录 |

观测帧的字段与编码见 `include/emaster/observation/wire.h`。设点记录见本文件最后一节。
部署 ID 不含 `-obs` / `-sp` 后缀，由配置校验保证，所以三条路径不会互相碰撞。

`tools/socket_bridge.py` 只把命令口与观测口转成 TCP 供另一台机器使用。设点口不转：
它是 `SOCK_SEQPACKET`，消息边界由内核给，转成字节流就得另加一层分帧。

## 命令通道

### 连接

单客户端。新连接到达时旧连接被关掉——两个客户端同时下命令没有仲裁依据。监听队列用
`SOMAXCONN`，断开后立刻重连不会被拒。

**空闲 5 秒即断开。** 监听线程靠 `SO_RCVTIMEO` 判断（`COMMAND_CLIENT_IDLE_TIMEOUT_S`）。
客户端进程被 kill 之后，流套接字上主站察觉不到，连接会一直挂着。把半开连接变成可回收
状态，下一次连接才能干净接手。客户端若要保持在线，至少每 5 秒说一句话。

**主站刚起来时套接字可能还没建好。** 连不上就退避重试，不要密集重连。

### 语法

一行为一条命令，以 `\n` 结束。命令与参数之间用一个空格分隔。空行不是命令。

| 命令 | 参数 | 作用 |
| --- | --- | --- |
| `stop` | 无 | 逐轴置 Halt（控制字 bit8），停运动但不退会话；`halt 0` 恢复 |
| `shutdown` | 无 | 请求停机并退出，`stop_source=command`。走与 SIGINT 相同的停机路径 |
| `status` | 无 | 读会话级计数与逐轴状态 |
| `dc` | 无 | 读 DC / SYNC0 的配置值与运行期相位 |
| `topology` | 无 | 读轴数、总线位置、编码器与齿轮比 |
| `switch <运动方案ID>` | 运动方案 ID | 换运动方案 |
| `set_external_target <q1> <q2> ...` | 每轴一个目标位置（原始计数） | 写外部目标汇点 |
| `quick_stop` | 无 | 逐轴请求 CIA402 Quick stop |
| `halt <0\|1>` | `1` 置位，其余清零 | 逐轴置 / 清 halt |
| `fault_reset` | 无 | 逐轴请求故障复位 |
| `recover_axis <轴号>` | 十进制轴号，从 0 起 | 恢复一台处于故障隔离的轴 |
| `sdo_read <从站号> <索引> <子索引>` | 从站号从 1 起；索引与子索引接受十进制或 `0x` 前缀 | 读任意对象字典条目 |
| `al` | 无 | 读每台配置从站的 AL 状态（0x0130）与 AL 状态码（0x0134） |

`recover_axis` 的解析分支是后补上的：在那之前枚举与处理分支都在，只有解析器里没有它的
分支，从套接字永远发不出去。**解析入口存在不代表这条恢复流程已验收。**

`sdo_read` 把请求交给观测线程执行，周期线程不做邮箱 I/O。一条请求在途时主站不接收
新命令，最多等 5 秒；超时回 `ERROR|sdo read timeout`，结果晚到也不再用它。成功时
正文是 `raw=<线序字节>`；1/2/4 字节再给出 `u=`（无符号）与 `i=`（补码有符号）。
SDO 载荷是小端。对象不存在、不可读或邮箱失败时回
`ERROR|sdo read failed: ...`，不把 0 当读数。

`al` 用同一套交接：请求交给观测线程，周期线程只等结果，在途时同样不接收新命令。
观测线程按**映射后的总线位置**对每台配置从站发两次 FPRD（单次超时 500 µs），
不调用 `ecx_readstate`。成功时正文是 `axes=<轴数>,ok=<有应答台数>`，随后每轴一段
`|a<轴号>:bus=<总线位置>,al=<状态>,code=<状态码>`；读不到的项印 `na`，不印 0。
零台有应答时回 `ERROR|al read failed: 0/<轴数> 台有应答`。状态码 `code` 只在 `al`
的 bit4（错误指示）置起时有含义；bit4 清零时不要用它判断故障。结果是读的那一拍的
快照，主站不缓存，也不周期轮询——每多一次轮询就是一份额外的总线流量。

`set_external_target` 的三个前提，任一不满足都返回 `ERROR`：

- 会话已配置外部目标汇点；
- 会话状态是 `RUNNING`（`state=4`）。这是为了防止 OP 之前注入目标导致首周期跳变；
- 参数个数与轴数完全相等。

目标离该轴当前位置太远时主站会**拒收这一条**：不中止会话，不改变其余轴，`status` 里的
`rejected=` 加一，`rej_axis=` / `rej_offset=` 给出最后一次拒收的轴号（从 1 起）与偏移计数；
报告里有同样的现场。这条线的宽度由部署键
`external_target_max_offset_millidegrees` 决定（默认 90°），按每轴自己的编码器与齿轮比
折算成原始计数，所以 25:1 与 28:1 的轴得到不同的线。

### 响应

每条命令回**一行**，格式：

```
OK|<正文>
ERROR|<正文>
```

正文里可能自己带 `OK|` / `ERROR|` 前缀——只有 `set_external_target` 这一条分支这么做。
所以那条命令成功时的整行是 `OK|OK|Updated 12 external targets`，失败时是
`ERROR|ERROR|Not ready: state=2 (need RUNNING=4)`。**其余命令都是单前缀。** 解析时按
第一个 `|` 切开取状态、其余全部是正文即可，正文里的 `|` 不必再切。

回写用 `MSG_DONTWAIT`，跑在实时周期线程上。客户端连上却不读，发送缓冲写满时不会阻塞
主站——短写与本该阻塞的两种情况一并按"这个客户端跟不上"处理：关掉连接，让它重连。
所以客户端读到的一行没有结尾换行就说明它不完整。响应正文多到放不下时末尾会出现
`|TRUNC`。

### 队列

命令先进队列（深度 16），由周期线程每拍取一条执行。队列满时主站回
`ERROR|Command queue full` 并丢弃这一条，同时在 stderr 记一行——队列满说明周期线程没在
取命令，是故障线索。

### 权限

套接字建好后 `chmod 0666`。主站以 root 启动，不改权限的话非 root 客户端连不上。这是刻意
的取舍：**任何能访问 `/tmp` 的本地用户都能控制电机，命令口与设点口都没有认证。**
多用户部署应改成 0660 并归于专用组。

## 遥测报文的形态

四个遥测命令（`status`、`topology`、`dc`、`al`）的正文都是「会话级字段在前，逐轴字段在后」的一段文本：

- 会话级字段是 `键=值`，用逗号连起来；
- 每根轴一段，以 `|a<序号>:` 开头，序号从 1 起，内部同样是 `键=值` 逗号分隔；
- 读不到的字段不编值，印明确的 "没读到"（如 `na`），不印 0——0 是一个看起来合理的读数。

`status` 以 `state=` 开头，含 `cycle`、`axes`、`enabled`、`completed`、`wkc`、
`wkc_expect`、`wkc_err`、`no_frame`、`over_budget`、`deadline_missed`、`rejected`、
`tgt_age_ms`、`rej_axis`、`rej_offset`、`cfg`。`cfg` 是主站加载的运行时配置指纹，
与报告里的 `deployment.config_fingerprint` 同值；主站没加载过配置时印 `na`。
逐轴字段含 `q=`（目标量的种类）与 `why=`
（轴不动的首要原因：`ok`、`fault`、`halt`、`disabled`、`mode`、`maxT`、`timeout`）。
`topology` 以 `axes=<轴数>,max_offset=<最小判据>` 开头，逐轴给
`bus`、`enc=<增量>/<电机转数>`、`gear=<电机转数>/<输出轴转数>`、`torque=0`、
`ser=<主站读到的序列号>`（读不到印 `na`）。`dc` 以 `required=` 开头。

完整的字段表由构造它们的那段代码定义（`src/bus/session/session_control.c` 中四个
`case EMASTER_COMMAND_QUERY_*`），仓库里参考的解析实现是 `tools/closed_loop_client.py`
、`tools/bench/test_external_motion_client.py` 与 `apps/status_client`（`--al`）。

## 设点通道

只写。整条链路上不存在会等客户端的点：没有响应、没有重试、没有回写接口。

**没有"就绪"握手。** 客户端连上就能发。挡"连上之前就发了一个离谱的值"的是目标判据
（目标离实际位置太远即拒收），它从第一拍起就生效。台架上的用法是先等 `status` 报
`state=4`，再起发送端。

### 记录格式

小端，定长，一条记录一次 `send`。**不 memcpy 结构体**：偏移、对齐、字节序都由这张表
定格，两端各写一份实现（`src/setpoint/wire.c` 与 `tools/setpoint_send.py`），
`tests/checks/setpoint_channel_check.py` 逐字节核对两者一致。

头部 24 字节：

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 2 | 魔数 `'E','S'` |
| 2 | 1 | 版本，当前 1 |
| 3 | 1 | 保留，0 |
| 4 | 2 | `record_bytes`，整条记录的长度（含头） |
| 6 | 2 | `axis_count`，1..16 |
| 8 | 8 | `sequence`，客户端给 |
| 16 | 8 | `client_time_ns`，客户端给 |

每轴 24 字节，从偏移 24 起连续排列：

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 1 | `mode`，有符号。8=CSP，9=CSV，10=CST |
| 1 | 1 | `flags`，主站原样存下、不解释 |
| 2 | 2 | 保留，0 |
| 4 | 4 | `q`，目标位置，原始计数 |
| 8 | 4 | `dq`，保留 |
| 12 | 4 | `tau`，保留 |
| 16 | 4 | `kp`，保留 |
| 20 | 4 | `kd`，保留 |

`record_bytes` 必须等于 `24 + 24 × axis_count`，对不上就整条拒收，不按轴数硬解。

### 单位

位置是**原始计数**，与观测通道同口径，换算由上层做。`kp` / `kd` 主站不解释。

**今天只有 `mode` 与 `q` 进输出路径。** `dq` / `tau` / `kp` / `kd` 会被解码、校验、
存进缓冲、计数，但不写进过程数据——驱动器在 CSP 下自己闭合位置环。这四个量等出口口径
定了再接。

### 拒收

拒收是局部的、可数的、不致命的：只丢这一条，会话继续，`status` 与报告里能看到次数、
最后一次的轴号与原因。原因只有四种：

| 原因 | 判据 |
| --- | --- |
| 记录超长 | 收到的字节数正好是接收缓冲容量（`最大合法记录 + 1`）。`SOCK_SEQPACKET` 截断过，长度不可信 |
| 格式不认识 | 魔数 / 版本 / `record_bytes` 与 `axis_count` 不自洽 / 轴数不在 1..16 |
| 轴数不符 | 记录里的轴数与本部署不相等。整条拒，不做部分采纳 |
| 模式不符 | 某轴的 `mode` 与本部署配的那一种不同 |

模式核对是 `mode` 这个字段今天唯一被消费的地方：同一条记录在两种模式下语义完全不同。
核对在写入之前，不匹配的记录一个字节都不进汇点。

序号只在**前进**时算缺口。回退或重复说明客户端重启或重放，那不是丢包。

### 例子

发送两个轴、目标各 1000 与 2000、200 Hz 保持 5 秒：

```sh
EMASTER_SETPOINT=1 ./build/linux-release/apps/master/emaster-master --deployment bench12 ...
python3 tools/setpoint_send.py --deployment bench12 --hold 1000 2000 --hz 200 --duration 5
```

发送端默认模式是 8（CSP），与部署配置一致才不被拒。离线核对波形与字节用 `--dry-run`。
