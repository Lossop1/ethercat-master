# 功能对标：按项目定位分层对标 TwinCAT（v2）

**范围**：只谈**功能**。不谈许可、安装包、生命周期、商务。

> **v2 修订说明（2026-10-14）**：v1 把 TwinCAT 的**整系统**功能面扣到一个**组件**上，把 NC 层的
> "运动规划、回零、速度/加速度上限"记成了本主站的 P0 差距，并给出"规划进主站"的路线选项。
> 这与项目定位矛盾：**本项目是执行层，规划属应用层**（见第 1 节证据）。v1 的 G-01（主站没有
> 运动规划器）与 G-07（插补/耦合/运动学）**已撤销**，回零（G-02）**重新界定为待定**。
> 结论：对标要**按层对**，不能整块搬。

## 1 项目定位（本主站是什么）

| 定位项 | 内容 | 证据 |
| --- | --- | --- |
| 产品定义 | "具有**安全阶段门**的多轴机器人 EtherCAT 主站"，C11 + SOEM，主站仅 Linux | `CMakeLists.txt:3-7`、`README.md:76` |
| 主站角色 | **执行层**：周期交换、CiA 402 状态机、逐级撤使能、单位换算、安全阶段门、报告与审计 | `README.md:427-448`、`docs/architecture.md:6,7` |
| 规划归属 | **应用层（ROS 2 / 上位机客户端）**；主站不生成轨迹、不限制步长与速度 | `docs/architecture.md:110`、`README.md:381` |
| 对外契约 | 应用层经 `position_target_source` 回调提交**完整轴集合**的目标；回调输入用当前周期反馈，输出已完成换算的目标计数 | `docs/architecture.md:110`、`config/README.md:192-194` |
| 上位机实例 | `/dev/shm` 上是 **ROS 2 运行时共享段**（`fastrtps_`），主站自己不用 | `docs/time-and-space.txt:50` |
| 主站唯一的运动判据 | `|目标 − 当前实际位置|` 超过偏移上限就拒收**这一条**，不中止会话 | `README.md:383` |
| 明确不做 | 热插拔、动态轴数、多主站协同、功能安全 | `README.md:465` |

**一句话**：主站负责"把这一拍的目标准确、按时、可取证地送达每一台驱动器"，**不负责决定目标是什么**。

## 2 因此：对标必须分层

TwinCAT 是**系统**（I/O + NC + PLC + 工程环境一体），本项目是**系统里的一层**。
把两者的功能面直接相减，得到的差距大半是"层次错位"，不是缺陷。

| TwinCAT 的层 | 本项目里对应的东西 | 对标对象 |
| --- | --- | --- |
| I/O 层：EtherCAT 主站 + System Manager 的总线组态与诊断 | **本主站**（就是你正在做的这棵树） | ✅ 对标这一层 |
| NC / NC PTP 层：轴、规划、回零、插补、耦合、运动学 | **上位机应用层（ROS 2）** | ❌ 不对标本主站 |
| PLC / 运行时 | 上位机应用层 | ❌ 不对标本主站 |
| Scope / 测量 | 主站的观测口 + 报告 + 离线分析工具（部分对应） | ⚠️ 部分对标 |
| TwinSAFE（认证安全） | 外部安全系统 + 本主站的**分级门** | ⚠️ 部分对标；认证安全明确不做 |

**修正后的对标口径**：只有"TwinCAT I/O 层 + System Manager 的组态/诊断能力"才是本主站的标尺；
"TwinCAT NC 层"要拿去对标**上位机**，不是拿去要求主站。

## 6 决策记录（2026-09-17 用户定）

1. **G-02 回零**：归执行层。范围是"把驱动器带进模式 6 并核对结果"，回零策略仍在上位机。
   模式集合已从 {8,9,10} 扩到含 6；17–35 是 0x6098 的方法号，不是 0x6060 的取值。
