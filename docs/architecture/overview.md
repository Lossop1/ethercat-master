# 架构与执行边界

目录按职责组织，CMake target 约束依赖。公共接口不暴露 SOEM 类型，业务参数只来自配置。
协议标准索引和数据类型属于实现知识，设备特性、拓扑数量、时序和运动限值属于配置。

## 主线与所有权

```text
部署 + 设备 + 拓扑 + 运行方案 + 运动方案
                    |
                会话计划
                    |
        总线配置 -> 周期启动 -> 周期控制 -> 退出
                    |           |
                  PDO编解码    CiA 402 + 多轴协调 + 轨迹
                    |
                 执行记录 -> 报告与中文展示
```

| 所有者 | 职责 |
|---|---|
| `config/`、`src/config/`、`src/catalog/` | 配置输入及其构建期生成目录 |
| `src/session/` | 按部署组合轴计划，检查实际布局和模式条件 |
| `src/protocol/` | 通用 PDO 发现模型、字段位置和整数编解码 |
| `src/cia402/` | 根据状态字与控制目标生成控制字，不访问总线或时钟 |
| `src/multiaxis/` | 完整轴集合、序号与截止时间检查 |
| `src/motion/` | 基于各轴真实换算因子的相对轨迹和跟随误差检查 |
| `src/bus/soem/` | 唯一 SOEM 集成边界，串行完成网络收发及状态切换 |
| `src/audit/` | 保存访问事实、连续同值合并、退出后序列化 |
| `tools/master/`、`src/messages/` | 入口、信号处理、报告发布和中文展示 |

`src/cyclic/` 保留总线无关的传输回调契约，`src/safety/` 保留通用条件汇总；
不能把库存在等同于当前会话已经接入其全部能力。

## 总线内部结构

`control_session.c` 只分配资源、调用各生命周期阶段并释放资源。
`session_internal.h` 是总线层私有的会话存储，不跨越 SOEM 边界。

| 文件 | 执行阶段与职责 |
|---|---|
| `session_setup.c` | 发现、身份核对、PDO 选择和映像、SDO 初始化、DC 与 SAFE-OP |
| `session_start.c` | 初始化输出，锁定实际位置，建立周期、启动参考时钟跟随并请求 OP |
| `session_exchange.c` | 定时、SOEM 过程数据交换、WKC 检查、DC 反馈和首次异常记录 |
| `session_control.c` | 解码反馈，调用独立控制器和轨迹模块，生成下一周期全轴输出 |
| `session_shutdown.c` | 逐级撤销使能并确认完整 CiA 402 停用状态，采集 AL 状态、关闭 Sync0、诊断并恢复 INIT |
| `cycle_clock.c` | Linux 单调时钟截止点与参考 DC 相位的 PI 修正 |
| `cia_process_image.c` | 已核对 PDO 布局的字段绑定、缓冲区编解码和直接索引审计 |
| `session_observer.c` | 类型明确的只读诊断及审计容量准备 |

总线层负责生命周期编排，不复制 CiA 402 状态规则或轨迹算法。不得为每台电机创建一套会话实现。

## 周期与并发

主线程按绝对截止点唤醒后立即发送，接收完成后再记录审计、计算相位修正、处理反馈与生成下一帧。
参数化的过程帧相位与 Sync0 偏移具有不同意义，周期线程不能以“固定休眠 1 ms”代替相位跟随。
期限已错过时退出正常控制，不连续补发历史帧，不自动放宽 WKC 判据。

PDO 审计游标按实际字段数量分配，每个字段直接查找上次记录。周期前预留并触及记录存储，
周期中不扩容、不写文件；容量耗尽后明确记录截断。周期线程不执行邮箱访问。
每个物理从站还分别聚合主机单调时间、参考 DC 时间、发送/往返耗时、发送迟到量和距 Sync0 的
理论裕量；这些数值用于定位时序，不能替代从站提供的 SM2 完成时间戳。

动态 PDO 直接提供模式反馈。固定 PDO 缺少模式反馈时，在 SAFE-OP 初始化阶段通过 SOEM SDO API
读回一次并在运行报告中保留；OP 周期不再访问邮箱，避免 SDO 与过程数据争用同一 SOEM 上下文。
当前控制会话只实现 CSP 的位置目标语义；设备目录声明的 CSV/CST 能力不会被伪装成可运行控制模式，
在对应目标量、反馈量、限幅和上层命令模型接入前，选择这些模式会被会话计划拒绝。

截止时间检查和 WKC 检查属于执行条件。诊断性模式反馈策略只允许保持位置；配置了变化轨迹
的轴必须匹配请求模式后才开始运动。所有轴在同一次协调步骤中处理，不发布部分目标集合。

## 失败与报告

首次周期失败保留状态、阶段、交换号、WKC 是否取得及最后参考时间，不被后续停机交换覆盖。
退出时的 AL 状态是退出快照，不冒充失败瞬间；过程数据访问成功也不等于电机完成指令。

停机尝试之后，先退出 OP，再关闭 Sync0 和读取诊断。最终诊断可能受状态转换影响，
报告以 `post_cycle_diagnostic` 标明阶段，不由末尾计数器反推首次异常顺序。
退出状态切换失败时跳过批量 SDO，继续关闭总线，绝不把缺少反馈当作停用成功。

报告文件在周期结束后原子发布。中文正文由消息目录管理，执行模块只返回结构化结果。

## 开发与产物

构建产物统一位于 `build/`，日常运行记录位于 `runtime/`，临时调查位于 `tmp/`。
不维护持久化测试程序、不创建独立测试工程；构建检查不能替代真机协议和运动验证。
已有调查证据保留，配置修改、说明与提交使用中文，当前架构文档只维护执行约定和职责。
