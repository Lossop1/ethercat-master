# EtherCAT主站错误恢复机制

## 设计目标

在不牺牲安全性的前提下，为可恢复的通信和状态错误提供自动恢复能力，减少人工干预。

## 错误分类

### 1. 不可恢复错误（立即停机，无自动恢复）
- 拓扑不匹配（从站数量、身份错误）
- PDO映射不匹配
- 内存分配失败
- 控制器内部故障
- 跟随误差超限
- 驱动器硬件故障

**策略：** 安全停机 → 记录故障 → 等待人工干预

### 2. 可恢复的通信错误
#### 2.1 WKC不匹配
- **原因：** 电缆松动、电磁干扰、从站瞬时无响应
- **检测：** `actual_wkc != expected_wkc`
- **恢复策略：**
  - 连续N次（建议3-5次）WKC错误 → 触发恢复
  - 单次WKC错误 → 计数但继续运行
  - 恢复动作：无（继续监控，累计过多则报警）
  - 超过阈值M次（建议50次/会话）→ 不可恢复，停机

#### 2.2 周期超时
- **原因：** CPU负载过高、实时性不足
- **检测：** deadline missed
- **恢复策略：**
  - 单次超时 → 记录警告，继续运行
  - 连续K次（建议10次）→ 不可恢复，停机

### 3. 可恢复的状态错误
#### 3.1 从站AL状态降级（OP → SAFE-OP）
- **原因：** DC同步丢失、SM事件错过
- **检测：** 定期检查AL状态
- **恢复策略：**
  1. 停止发送新目标
  2. 设置控制字为安全停止
  3. 尝试重新请求OP（最多R次，建议3次）
  4. 成功 → 恢复运动控制
  5. 失败 → 降级为不可恢复错误

#### 3.2 CiA 402状态异常退出
- **原因：** 驱动器内部保护、控制字序列异常
- **检测：** 状态字bit 3 (fault) = 1
- **恢复策略：**
  1. 读取故障对象（603F、1001、203E、203F）
  2. 如果是软件可恢复故障（通信超时、参数警告）
     - 执行Fault Reset（控制字bit 7: 0→1）
     - 重新执行使能序列
  3. 如果是硬件故障 → 不可恢复

## 实现计划

### 阶段1：WKC容错增强
- 添加每轴WKC错误计数器
- 单次WKC不匹配 → 记录但不停机
- 连续或累计错误达阈值 → 触发停机
- 配置参数：
  - `wkc_consecutive_error_threshold` (默认5)
  - `wkc_total_error_threshold` (默认50)

### 阶段2：AL状态监控与恢复
- 在cyclic_operation阶段定期检查从站AL状态
- 检测到降级 → 尝试重新请求OP
- 添加配置参数：
  - `al_recovery_max_attempts` (默认3)
  - `al_state_check_interval_cycles` (默认100)

### 阶段3：CiA 402故障恢复
- 检测fault bit → 读取故障对象
- 根据故障类型决定是否尝试reset
- 添加故障码白名单（可自动恢复的故障类型）
- 配置参数：
  - `fault_reset_max_attempts` (默认3)
  - `recoverable_fault_codes[]` (配置白名单)

## 安全约束

1. **恢复尝试次数限制：** 所有自动恢复都有最大尝试次数
2. **恢复期间安全状态：** 恢复过程中保持安全停止
3. **运动中断：** 任何恢复都会中断当前运动轨迹
4. **审计记录：** 所有恢复尝试和结果都记录到审计报告
5. **人工优先：** stop_requested始终优先于自动恢复

```json
    },

      "recovery_enabled": false,
      "recoverable_codes": [8600, 8611]
    }
  }
}
```
