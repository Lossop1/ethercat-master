# 设备描述

**这个目录出厂是空的。** 放入你手上那台电机的 ESI 文件（XML），
一台型号一个目录，名字随意 —— 只有文件内容会进后续步骤，目录名不参与任何判定。

文件随便放哪一层都行，工具按后缀找 `.xml`：

```
esi/
  你的型号/
    ECAT_CIA402.xml
```

## 从哪来

问电机的厂商要 ESI（XML）。有些厂商只给 EDS（CANopen）或纸质手册里的对象表，
**本项目读不了这两种** —— 工具只认 `.xml`，给别的后缀会直接报错退出，不会解析出一半
再崩。ESI 是唯一能自动化的来源：里面的 PDO 映射、条目位宽、对象字典是机器可读的，
换一款电机必须重抄的就是这些。只要拿不到 ESI，那几项就得照手册手抄进设备档。
厂商手册（PDF、接线图）是给人看的，放在你自己那边，不必进这个仓库。

## 拿它做什么

```
python gen/emaster_config.py add-device esi/你的型号/xxx.xml
```

这一步把 ESI 里的硬件事实（身份、PDO 映射、条目位宽、支持的模式）抽出来，生成一份
设备档草稿和一份策略档草稿。然后人和台架补上推不出来的那几个字段，再跑：

```
python gen/emaster_config.py build
```

四族扁平文件写到 `config-runtime/`，主站 `--config-dir config-runtime` 读它。
完整流程见 `gen/device/README.md` 与 `README.md` 的"快速上手"一节。

## 为什么不入库

仓库里留的是**代码**，不含任何具体电机的配置。这样第三方拿到的是同一份主站，
换上自己那台电机的 ESI 就能跑，不需要重编 —— 也不需要知道台架上是哪款电机。
