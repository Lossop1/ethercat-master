2026-09-17，五轴台架 orangepi-bench-quint-30deg

【怎么跑的】
  面板   tools/emaster_console.py --deployment orangepi-bench-quint-30deg --range 3
  驱动   scripts/bench_panel_drive.sh（pty 喂键：g → 1:0.5 4:0.5 → 回车 → t 20 秒 → t → 0 → Q）
  解析   scripts/analysis/panel_transcript.py
  原始转录与主站日志是台架 /tmp 里的一次性产物，没有进仓库；重跑上面那条即可再生。

【读数】

1) 不滚屏
   绘制区 401 帧，全部用绝对定位；用到行号 1..15（终端 24 行）。
   面板自己的输出里：\r 0 个、\n 0 个。
   转录里唯一的那个 \n 在字节 198，紧接在 \x1b[?1049h 之前 —— 是 script(1) 写的头，
   不是面板发的（这一点按字节定位核过，不是靠肉眼）。
   进/出备用屏幕各 1 次；光标隐藏/恢复各 1 次。
   ⇒ 面板一个换行符都没发过，终端不可能被顶滚。

2) 打字不打断控制流
   带输入行的帧 20 个，输入行从 "> ▏" 长到 "> 1:0.5 4:0.5▏"。
   这段时间里帧上的拍号从 214484 走到 216385（推进 1901 拍）。
   ⇒ 打字期间面板的控制拍照常在跑（旧版的阻塞 input() 会让这几秒的拍号不动）。

3) 多轴同时起停
   命令 1:0.5 4:0.5，轴1 与轴4 同时离开零点（|角度|>0.02°）的帧 313 个。
   轴4 全程 -0.29°..+0.79°，结算在 +0.50°。

4) 往返验证
   轴1 实际位置 -0.14°..+1.91°（振幅 1.8°）；面板记账 200 帧，末条 "1/1.8/0:19/33/0"。
   收尾汇总：往返验证结束：33 趟，异常 0 条。

5) 主站日志
   37 行，其中 [MODE] 8 条 = 进入 EXTERNAL 4 次 / 超时回 HOLD 4 次。
   没有 released / abort / MOTION_INVALID 字样，会话没有中止过。

【没证到的（别当成证过了）】

* "打字窗口里主站保持 EXTERNAL" 这条**没有证据**。主站日志没有时间戳，
  那 4 对 [MODE] 切换没法对齐到面板的哪一步动作；而面板不发目标时主站本来就该
  超时回 HOLD（200 ms 看门狗在干活），所以 HOLD 的条数本身说明不了任何事。
  ⇒ 登记在 docs/requirements/layering-plan.md P10.4。

* 新版点动（按下就走 / 按住连续 / 松手停）**没在台架上跑过**：取证时命令套接字
  被现场开着的面板进程占着（该套接字一次只接一个客户端），台架那一半没跑成。
  它在离线回归里过了（见下）。

【离线回归（同一轮，本机 Windows，不连主站、不要终端）】
  命令   PYTHONIOENCODING=utf-8 python scripts/checks/console_engine_check.py --selftest
  退出码 0，六节全过：
    1) 斜坡走 1° 再回起点，五轴都回到起点附近
    2) 目标序列最大相邻增量 254 counts ≤ 上限 5120（= max_step×0.8）
    3) 状态字解析：五轴 0x0427，没有误判成未使能
    4) 急停与复位后主站仍 RUNNING
    5) 软范围 ±45° 拦截：越界目标整条命令都没发，主站未受影响
    6) 按键层：选区 / 点动（第一拍就走、按住 0.6 秒走 3.72°、松手停住、被软范围夹住）/
       输入行编辑与提交 / 多轴同时起停 / 姿态槽 / 调速 / 回起点 / 重锚零点 / 往返开关 / 帮助
  负对照有效：故意发一步 999999 → 假主站确实把整个会话打掉（判据不是摆设）。
